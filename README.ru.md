## Почему DSH Game Studio

Попросите агента создать игру простыми словами — «3D-игра: красная панда собирает побеги бамбука в лесу и уворачивается от диких кабанов» — и он соберёт её из шаблона, сам сыграет в неё для проверки работоспособности и покажет на боковой панели, где в неё можно сразу поиграть. Изначально персонажи рисуются кодом; когда вам понадобится настоящая графика, агент сгенерирует варианты через OpenAI или вашу учётную запись Codex, вы выберете нужный по номеру, и игра подставит его. Каждое изменение сохраняется как версия, к которой можно вернуться, а готовая игра экспортируется в виде единого автономного HTML-файла.

| | |
| --- | --- |
| 🎮 **Можно играть с первого же ответа** | Два шаблона — 2D-игра с видом сверху и тот же игровой цикл в воксельном 3D-мире (three.js), — которые агент перестраивает под описанную вами игру: персонажи, правила, уровни, экраны. |
| 🖥️ **Живой предпросмотр на боковой панели** | Игра запускается в изолированной панели рядом с чатом, пересобирается при каждом изменении и выводит под собой список слотов графики, вариантов и версий. Игры в горизонтальной ориентации получают широкую сцену. |
| 🎨 **Своя графика с предварительной проверкой стоимости** | `game_studio_generate_asset` создаёт пронумерованные варианты для каждого слота через API изображений OpenAI или локальный Codex CLI. До списания средств вы получаете карточку подтверждения с указанием сервиса, количества изображений и ожидаемой стоимости. Прикреплённая в чате картинка может служить референсом. |
| 🤖 **Автоматические плейтесты** | `game_studio_playtest` запускает свежий код в безголовом (headless) режиме Chrome или Edge и возвращает отчёт по фазам, очкам, частоте кадров, ошибкам скриптов и скриншотам. Игры, в которых управление осуществляется не стрелками (сетки, карты, прицеливание, ритм-игры…), определяют `window.__autoplay`, поэтому плейтест проходит их реальный игровой цикл. |
| 🕰️ **История версий** | Каждая сборка, изменившая игру, сохраняется; `game_studio_restore_version` возвращает код, правила и графику вместе. |
| 📦 **Экспорт в один файл** | `game_studio_export` записывает полностью автономный HTML-файл без доступа к сети — откройте его в любом браузере или разместите на любом статическом хостинге. |
| 📱 **Проверка на телефоне** | `game_studio_share` открывает временную ссылку только для чтения в вашей локальной сети с QR-кодом на боковой панели. |
| 🗂️ **Мои игры** | Нажмите **+** в правой панели и выберите **Game Studio · My games**: каждая игра рабочей области — плитка с кадром последнего теста, с фильтром 2D/3D и сортировкой по дате, версиям или названию. Один клик — и играете, без агента и без токенов. **Export wall** собирает показанные игры в одну офлайн-страницу, которую можно отправить друзьям. |

## Насколько хорошо это работает

Измерено в реальном DSH с моделью DeepSeek-V4.1-Flash: каждая игра создавалась из одного предложения в новой сессии и оценивалась независимым плейтестом (2026-11-04/05):

- **Игры в жанре «собирай и уворачивайся»** (основная специализация шаблонов): 10 из 10 различных запросов оказались полностью играбельными с первой попытки, медианное время — около 14 минут на игру.
- **Другие жанры** — три в ряд, перемещение ящиков (сокобан), башенная защита (tower defense), баскетбол, платформер, ритм-игра, гонки, карточный баттлер, ферма, управление кафе: все 10 оказались играбельными, но заняли в среднем (по медиане) около 26 минут. После добавления `__autoplay`, пользовательских слотов графики и горизонтальной ориентации четыре из них были запущены повторно и заняли 8–18 минут. Выборка небольшая.

## Инструменты

| Инструмент | Что он делает |
| --- | --- |
| `game_studio_create` | Создаёт играбельную игру из шаблона `collector` (2D) или `voxel` (3D), собирает её и показывает на боковой панели. Принимает название, художественный стиль, `orientation` (портретная или горизонтальная) и `slots` — собственные графические слоты игры, названные на языке пользователя. |
| `game_studio_build` | Пересобирает проект после редактирования `game.json` или `game.js`, обновляет предпросмотр и сохраняет версию с краткой заметкой. |
| `game_studio_playtest` | Запускает свежий код в безголовом режиме (портретный формат под телефон или горизонтальный 960×540) и сообщает фазы, лучший счёт, жизни, частоту кадров, ошибки и скриншоты; параметр `characters: true` возвращает только крупные планы персонажей. |
| `game_studio_generate_asset` | Генерирует от 1 до 4 вариантов изображений для одного слота с помощью `openai` или `codex`, при необходимости опираясь на изображение-референс. Запрашивает подтверждение перед расходом средств. Codex работает в фоновом режиме. |
| `game_studio_apply_asset` | Подставляет выбранный вариант в игру по его номеру, пересобирает проект и обновляет предпросмотр. |
| `game_studio_revert_asset` | Возвращает предыдущую графику слота. |
| `game_studio_versions` | Выводит список сохранённых версий, начиная с самых новых. |
| `game_studio_restore_version` | Восстанавливает более раннюю версию всей игры целиком. |
| `game_studio_export` | Экспортирует один автономный HTML-файл, работающий без интернета. |
| `game_studio_share` | Открывает (или закрывает) временную ссылку только для чтения в локальной сети, чтобы в игру можно было поиграть с телефона. |
| `game_studio_list` | Показывает игры рабочей области с названием, 2D/3D, состоянием сборки и числом версий, чтобы агент находил «ту игру с пингвином» по имени. |
| `game_studio_export_wall` | Экспортирует стену игр: офлайн-страница HTML с плиткой для каждой собранной игры; клик по плитке запускает игру. |

Кнопки на боковой панели (применить, вернуть, собрать, экспортировать, восстановить, поделиться) вызывают те же самые операции через команду `/game-studio`.

## Сервисы генерации изображений и расходы

| Сервис | Что требуется | Стоимость | Примечания |
| --- | --- | --- | --- |
| **OpenAI** (GPT Image) | API-ключ в учётных данных DSH или в переменной окружения (по умолчанию `OPENAI_API_KEY`) | Оплата за каждое изображение списывается с вашего ключа; карточка подтверждения показывает расчётную стоимость | Около минуты на пакет. `openaiBaseUrl` принимает шлюз, совместимый с OpenAI. |
| **Codex CLI** | Установленный и авторизованный Codex (`codex login`) | Расходует лимиты вашего тарифа Codex; API-ключ не требуется | Несколько минут на изображение, работает в фоновом режиме и сообщает о готовности по завершении. |

Режим `imageProvider: auto` (по умолчанию) использует OpenAI, если задан его ключ, а в противном случае — Codex. При включённом `confirmSpending` (по умолчанию) ничего не генерируется, пока вы не одобрите карточку. Спрайты проверяются на прозрачность фона и кадрирование, а затем подгоняются под размер слота перед тем, как будут предложены вам.

## Безопасность и конфиденциальность

- Игры запускаются в изолированном `iframe` с политикой безопасности контента (CSP), которая блокирует доступ к сети; экспортированные файлы не выполняют никаких сетевых запросов.
- Единственное, что отправляется с вашего компьютера наружу — это промпты (и картинка-референс, если вы её приложили) в выбранный вами сервис генерации изображений.
- Ссылка для общего доступа работает только в режиме чтения, раздаёт только сборку конкретной игры, слушает только вашу локальную сеть и закрывается по истечении заданного времени (по умолчанию 30 минут).
- API-ключи считываются из учётных данных DSH или переменных окружения и никогда не записываются в файлы проектов, логи или результаты работы инструментов.

## Требования

- DeepSeek Harness `0.2.1` или новее (веб- или настольная версия), Node.js `24.11` или новее.
- Google Chrome или Microsoft Edge на том же компьютере для запуска плейтестов.
- Для ИИ-графики: либо API-ключ OpenAI, либо авторизованный Codex CLI. Без них игры всё равно работают со своими персонажами, нарисованными кодом.

## Конфигурация

Задайте эти параметры в разделе `config` файла `cordis.patch.yml` вашего профиля:

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `imageProvider` | `auto` | `auto`, `openai` или `codex`. |
| `openaiModel` | `gpt-image-2.5-flare` | Модель генерации изображений OpenAI; зафиксируйте её, чтобы результаты оставались сопоставимыми. |
| `openaiBaseUrl` | OpenAI | Базовый URL, совместимый с OpenAI, например корпоративный шлюз. |
| `openaiCredential` | `OPENAI_API_KEY` | Имя учётных данных или переменной окружения, содержащей ключ. |
| `codexPath` | ищется в `PATH` или через оболочку входа (login shell) | Исполняемый файл Codex CLI. |
| `codexModel` | по умолчанию в Codex | Модель для генерации изображений через Codex. |
| `codexReasoningEffort` | `low` | Уровень усилий на рассуждение (reasoning effort) при генерации изображений в Codex. |
| `codexTimeoutMinutes` | `15` | Прервать генерацию одного изображения в Codex по истечении этого времени (в минутах). |
| `confirmSpending` | `true` | Запрашивать подтверждение перед каждой генерацией. |

## Формат игрового проекта

Каждая игра представляет собой обычную папку в вашем рабочем пространстве:

- `game.json` — название, художественный стиль, ориентация, слоты графики и правила. Правила имеют свободную форму: любой ключ передаётся в игру как `window.GAME.rules`.
- `game.js` — код игры, который редактирует агент. Он предоставляет `window.__gameState()` для плейтестов, опционально `window.__autoplay(state)` для игр, не управляемых стрелками, и `window.__renderSlots(size)`, чтобы боковая панель отображала персонажей, нарисованных кодом (2D-шаблон рисует их в `drawCharacter()`).
- `assets/` — изображение для каждого слота плюс `ASSETS.json` — запись о том, откуда взялось каждое из них. Вы можете рисовать поверх файла слота напрямую; студия запишет это как вашу правку.
- `dist/index.html` — текущая сборка; в папке `.studio/` хранятся версии, варианты графики и запуски плейтестов.

## Разработка

```sh

npm run build   # lib/index.js, lib/client.js and the bundled three.js runtime
```
