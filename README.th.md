## ทำไมต้อง DSH Game Studio

เพียงสั่งให้เอเจนต์สร้างเกมด้วยคำพูดธรรมดา — "เกม 3D: แพนด้าแดงเก็บหน่อไม้ในป่าและคอยหลบหมูป่า" — เอเจนต์ก็จะสร้างเกมขึ้นจากเทมเพลต ทดลองเล่นเพื่อตรวจสอบว่าใช้งานได้จริง และแสดงผลในแถบด้านข้างให้คุณเข้าเล่นได้ทันที ตัวละครจะเริ่มต้นจากโมเดลที่วาดด้วยโค้ด และเมื่อคุณต้องการภาพอาร์ตจริง เอเจนต์จะสร้างภาพตัวเลือกด้วย OpenAI หรือบัญชี Codex ที่คุณลงชื่อเข้าใช้ไว้ ให้คุณเลือกจากหมายเลข แล้วตัวเกมจะสลับภาพเข้าไปแทนที่ทันที ทุกการเปลี่ยนแปลงจะถูกบันทึกเป็นเวอร์ชันที่คุณย้อนกลับไปได้ และเมื่อเสร็จสมบูรณ์ก็สามารถส่งออกตัวเกมเป็นไฟล์ HTML แบบออฟไลน์เพียงไฟล์เดียวได้

| | |
| --- | --- |
| 🎮 **เล่นได้ตั้งแต่คำตอบแรก** | มีสองเทมเพลต — เกม 2D มุมมองจากด้านบน และเกมรูปแบบเดียวกันในโลก 3D voxel (three.js) — ซึ่งเอเจนต์จะปรับแต่งให้กลายเป็นเกมตามที่คุณอธิบาย ทั้งตัวละคร กฎกติกา ด่าน และหน้าจอต่าง ๆ |
| 🖥️ **พรีวิวสดในแถบด้านข้าง** | เกมจะรันอยู่ในพาเนลแบบแซนด์บ็อกซ์ถัดจากบทสนทนา บิลด์ใหม่ทุกครั้งที่มีการแก้ไข และแสดงรายการช่องใส่ภาพอาร์ต (slot) ภาพตัวเลือก และเวอร์ชันต่าง ๆ ไว้ด้านล่าง ส่วนเกมแนวนอนจะได้พื้นที่แสดงผลแบบกว้าง |
| 🎨 **ภาพอาร์ตของคุณเอง พร้อมตรวจสอบค่าใช้จ่ายก่อนเสมอ** | `game_studio_generate_asset` จะสร้างภาพตัวเลือกที่มีหมายเลขกำกับสำหรับแต่ละช่องด้วย OpenAI image API หรือ Codex CLI ในเครื่อง ก่อนที่จะมีค่าใช้จ่ายใด ๆ คุณจะได้รับการ์ดขออนุมัติที่ระบุบริการ จำนวนภาพ และค่าใช้จ่ายที่คาดการณ์ไว้ และคุณยังสามารถแนบรูปภาพในแชทเพื่อใช้เป็นภาพอ้างอิงได้ด้วย |
| 🤖 **การทดสอบเล่นอัตโนมัติ** | `game_studio_playtest` จะเล่นโค้ดล่าสุดใน Chrome หรือ Edge แบบ headless และรายงานเฟสของเกม คะแนน เฟรมเรต ข้อผิดพลาดของสคริปต์ และภาพหน้าจอ ส่วนเกมที่ไม่ได้บังคับด้วยปุ่มลูกศร (เช่น เกมตาราง การ์ด เล็งเป้า จังหวะดนตรี…) จะกำหนด `window.__autoplay` ไว้ เพื่อให้การทดสอบเล่นสามารถเล่นตามลูปจริงของเกมได้ |
| 🕰️ **ประวัติเวอร์ชัน** | ทุกบิลด์ที่มีการเปลี่ยนแปลงตัวเกมจะถูกบันทึกไว้ โดย `game_studio_restore_version` จะกู้คืนทั้งโค้ด กฎกติกา และภาพอาร์ตกลับมาพร้อมกัน |
| 📦 **ส่งออกเป็นไฟล์เดียว** | `game_studio_export` จะเขียนไฟล์ HTML ที่ครบจบในตัวเองโดยไม่ต้องเชื่อมต่อเครือข่าย — เปิดเล่นในเบราว์เซอร์ใดก็ได้ หรือนำไปวางบนโฮสต์สำหรับไฟล์สแตติกได้ทุกที่ |
| 📱 **ลองเล่นบนโทรศัพท์ของคุณ** | `game_studio_share` จะเปิดลิงก์แบบอ่านอย่างเดียวชั่วคราวบนเครือข่ายในบ้านหรือวงแลนของคุณ พร้อมแสดงคิวอาร์โค้ดในแถบด้านข้าง |
| 🗂️ **เกมของฉัน** | กด **+** ที่แถบด้านขวาแล้วเลือก **Game Studio · My games** ทุกเกมในเวิร์กสเปซจะแสดงเป็นไทล์พร้อมภาพจากการทดสอบเล่นครั้งล่าสุด กรองตาม 2D/3D และเรียงตามเวลา จำนวนเวอร์ชัน หรือชื่อได้ คลิกเดียวก็เล่นได้ ไม่ต้องผ่าน agent และไม่ใช้โทเคน **Export wall** รวมเกมที่แสดงอยู่เป็นหน้าเว็บออฟไลน์หน้าเดียวส่งให้เพื่อนได้ |

## ประสิทธิภาพการใช้งานจริง

วัดผลใน DSH จริงร่วมกับ DeepSeek-V4.1-Flash โดยสร้างแต่ละเกมจากประโยคเดียวในเซสชันใหม่ และประเมินผลด้วยการทดสอบเล่นที่เป็นอิสระ (2026-11-04/05):

- **เกมแนวเก็บของและหลบหลีก** (แนวถนัดของเทมเพลต): คำขอที่แตกต่างกัน 10 จาก 10 รายการสามารถเล่นได้ตั้งแต่ครั้งแรก โดยมีค่ามัธยฐานอยู่ที่ประมาณ 14 นาทีต่อเกม
- **เกมแนวอื่น ๆ** — เรียงเพชร (match-3), ดันกล่อง, ป้องกันฐาน (tower defense), บาสเกตบอล, แพลตฟอร์มเมอร์, จังหวะดนตรี, แข่งรถ, การ์ดแบตเทิล, ทำฟาร์ม, บริหารคาเฟ่: ทั้ง 10 เกมออกมาเล่นได้จริง แต่ใช้เวลาโดยมีค่ามัธยฐานอยู่ที่ประมาณ 26 นาที หลังจากเพิ่ม `__autoplay`, ช่องใส่ภาพอาร์ตแบบกำหนดเอง และการรองรับหน้าจอแนวนอน ได้นำเกม 4 รายการมารันใหม่และใช้เวลา 8–18 นาที ทั้งนี้กลุ่มตัวอย่างยังมีขนาดเล็ก

## เครื่องมือ

| เครื่องมือ | หน้าที่การทำงาน |
| --- | --- |
| `game_studio_create` | สร้างเกมที่เล่นได้จากเทมเพลต `collector` (2D) หรือ `voxel` (3D) พร้อมบิลด์และแสดงผลในแถบด้านข้าง รับค่าชื่อเกม สไตล์ภาพอาร์ต `orientation` (แนวตั้งหรือแนวนอน) และ `slots` — ช่องใส่ภาพอาร์ตเฉพาะของเกมนั้น ๆ ซึ่งตั้งชื่อตามภาษาของผู้ใช้ |
| `game_studio_build` | บิลด์ใหม่หลังจากแก้ไข `game.json` หรือ `game.js` รีเฟรชหน้าพรีวิว และบันทึกเป็นเวอร์ชันพร้อมข้อความบันทึกสั้น ๆ |
| `game_studio_playtest` | เล่นโค้ดล่าสุดแบบ headless (แนวตั้งทรงหน้าจอโทรศัพท์ หรือแนวนอนขนาด 960×540) และรายงานเฟส คะแนนสูงสุด หัวใจ fps ข้อผิดพลาด และภาพหน้าจอ หากกำหนด `characters: true` จะส่งกลับเฉพาะภาพระยะใกล้ของตัวละครเท่านั้น |
| `game_studio_generate_asset` | สร้างภาพตัวเลือก 1–4 ภาพสำหรับหนึ่งช่องด้วย `openai` หรือ `codex` โดยเลือกอ้างอิงตามภาพต้นแบบได้ จะขออนุมัติก่อนมีค่าใช้จ่ายเสมอ ทั้งนี้ Codex จะทำงานในพื้นหลัง |
| `game_studio_apply_asset` | นำภาพตัวเลือกใส่เข้าไปในเกมตามหมายเลข บิลด์ใหม่ และรีเฟรช |
| `game_studio_revert_asset` | ย้อนกลับไปใช้ภาพอาร์ตก่อนหน้าของช่องนั้น |
| `game_studio_versions` | แสดงรายการเวอร์ชันที่บันทึกไว้ โดยเรียงจากใหม่ล่าสุดก่อน |
| `game_studio_restore_version` | กู้คืนตัวเกมทั้งหมดกลับไปยังเวอร์ชันก่อนหน้า |
| `game_studio_export` | ส่งออกเป็นไฟล์ HTML แบบออฟไลน์ที่ครบจบในตัวเองเพียงไฟล์เดียว |
| `game_studio_share` | เปิด (หรือปิด) ลิงก์แบบอ่านอย่างเดียวชั่วคราวบนเครือข่ายในพื้นที่ เพื่อให้โทรศัพท์สามารถเข้าเล่นเกมได้ |
| `game_studio_list` | แสดงรายการเกมในเวิร์กสเปซพร้อมชื่อ 2D/3D สถานะบิลด์ และจำนวนเวอร์ชัน ให้ agent หา "เกมเพนกวินนั้น" จากชื่อได้ |
| `game_studio_export_wall` | ส่งออกกำแพงเกม: หน้า HTML ออฟไลน์ที่มีไทล์ละเกมสำหรับทุกเกมที่บิลด์แล้ว คลิกไทล์เพื่อเล่น |

ปุ่มต่าง ๆ ในแถบด้านข้าง (นำไปใช้, ย้อนกลับ, บิลด์, ส่งออก, กู้คืน, แชร์) จะเรียกใช้งานการทำงานเดียวกันนี้ผ่านคำสั่ง `/game-studio`

| บริการ | สิ่งที่ต้องใช้ | ค่าใช้จ่าย | หมายเหตุ |
| --- | --- | --- | --- |
| **OpenAI** (GPT Image) | คีย์ API ในข้อมูลรับรองของ DSH หรือตัวแปรสภาพแวดล้อม (ค่าเริ่มต้นคือ `OPENAI_API_KEY`) | เรียกเก็บเงินตามจำนวนภาพผ่านคีย์ของคุณ โดยการ์ดขออนุมัติจะแสดงราคาประเมินให้เห็น | ใช้เวลาประมาณหนึ่งนาทีต่อชุด โดย `openaiBaseUrl` รองรับเกตเวย์ที่เข้ากันได้กับ OpenAI |
| **Codex CLI** | ติดตั้ง Codex และลงชื่อเข้าใช้แล้ว (`codex login`) | หักตามโควตาแพ็กเกจ Codex ของคุณ ไม่ต้องใช้คีย์ API | ใช้เวลาหลายนาทีต่อภาพ ทำงานในพื้นหลังและจะรายงานผลเมื่อเสร็จสิ้น |

`imageProvider: auto` (ค่าเริ่มต้น) จะใช้ OpenAI เมื่อมีการตั้งค่าคีย์ไว้ และจะใช้ Codex ในกรณีอื่น ๆ เมื่อเปิดใช้งาน `confirmSpending` (ค่าเริ่มต้น) ระบบจะไม่สร้างภาพใด ๆ จนกว่าคุณจะกดอนุมัติในการ์ด ภาพสไปรต์จะถูกตรวจสอบความโปร่งใสของพื้นหลังและระยะขอบภาพ รวมถึงปรับขนาดให้พอดีกับช่องก่อนนำมาเสนอให้คุณเลือก

## ความปลอดภัยและความเป็นส่วนตัว

- เกมจะรันอยู่ใน iframe แบบแซนด์บ็อกซ์พร้อมนโยบายความปลอดภัยของเนื้อหา (CSP) ที่บล็อกการเข้าถึงเครือข่าย และไฟล์ที่ส่งออกจะไม่มีการส่งคำขอเครือข่ายใด ๆ
- สิ่งเดียวที่จะถูกส่งออกจากเครื่องของคุณคือคำสั่งพรอมต์ — และภาพอ้างอิง หากคุณแนบมา — เพื่อส่งไปยังบริการสร้างภาพที่คุณเลือกเท่านั้น
- ลิงก์สำหรับแชร์เป็นแบบอ่านอย่างเดียว ให้บริการเฉพาะบิลด์ของเกมนั้น เปิดรับการเชื่อมต่อภายในเครือข่ายในพื้นที่ของคุณเท่านั้น และจะปิดลงหลังจากครบเวลาที่คุณตั้งไว้ (ค่าเริ่มต้นคือ 30 นาที)
- คีย์ API จะถูกอ่านจากข้อมูลรับรองของ DSH หรือตัวแปรสภาพแวดล้อม และจะไม่ถูกเขียนลงในโปรเจกต์ ล็อก หรือผลลัพธ์ของเครื่องมือเด็ดขาด

## เริ่มต้นใช้งานอย่างรวดเร็ว

เปิดเซสชันในโฟลเดอร์เวิร์กสเปซ แล้วลองสั่งตัวอย่างเช่น:

- `สร้างเกมเล็ก ๆ: ลูกแมวขโมยปลาแห้งในห้องครัวโดยไม่ให้ชนเข้ากับหุ่นยนต์ดูดฝุ่น`
- `สร้างเกม 3D: อัศวินตัวน้อยเก็บเหรียญในปราสาทและคอยหลบโครงกระดูก เก็บครบ 20 เหรียญภายใน 60 วินาทีจะชนะ`
- `สร้างเกมเรียงเพชร (match-3) บนตารางขนาด 6×6 ทำคะแนนให้ถึง 1000 แต้มภายใน 60 วินาทีเพื่อชนะ`

จากนั้นลองสั่ง:

- `สร้างภาพอาร์ตใหม่ 2 ภาพสำหรับตัวละครเอกด้วย AI เดี๋ยวฉันจะเลือกในแถบด้านข้างเอง`
- `อ้างอิงตามรูปภาพที่ฉันแนบไปสำหรับรูปลักษณ์ของตัวละครเอก`
- `ส่งออกเป็นไฟล์ HTML ไฟล์เดียว`

## การตั้งค่า

กำหนดค่าเหล่านี้ภายใต้ `config` ในไฟล์ `cordis.patch.yml` ของโปรไฟล์คุณ:

| ตัวเลือก | ค่าเริ่มต้น | ความหมาย |
| --- | --- | --- |
| `imageProvider` | `auto` | `auto`, `openai` หรือ `codex` |
| `openaiModel` | `gpt-image-2.5-flare` | โมเดลสร้างภาพของ OpenAI กำหนดไว้เพื่อให้ผลลัพธ์ยังคงเปรียบเทียบกันได้ |
| `openaiBaseUrl` | OpenAI | Base URL ที่เข้ากันได้กับ OpenAI เช่น เกตเวย์ของบริษัท |
| `openaiCredential` | `OPENAI_API_KEY` | ชื่อของข้อมูลรับรองหรือตัวแปรสภาพแวดล้อมที่เก็บคีย์ไว้ |
| `codexPath` | ค้นหาจาก `PATH` หรือผ่านเชลล์ล็อกอิน | ไฟล์สั่งทำงานของ Codex CLI |
| `codexModel` | ค่าเริ่มต้นของ Codex | โมเดลสำหรับการรันสร้างภาพด้วย Codex |
| `codexReasoningEffort` | `low` | ระดับการใช้เหตุผล (reasoning effort) สำหรับการรันสร้างภาพด้วย Codex |
| `codexTimeoutMinutes` | `15` | ยกเลิกการสร้างภาพหนึ่งภาพด้วย Codex หากใช้เวลานานเกินค่านี้ (นาที) |
| `confirmSpending` | `true` | ขออนุมัติก่อนการสร้างภาพทุกครั้ง |

## รูปแบบโปรเจกต์เกม

แต่ละเกมจะเป็นโฟลเดอร์ธรรมดาในเวิร์กสเปซของคุณ:

- `game.json` — ชื่อเกม สไตล์ภาพอาร์ต แนวหน้าจอ ช่องใส่ภาพอาร์ต และกฎกติกา โดยกฎกติกามีรูปแบบอิสระ คีย์ใด ๆ จะถูกส่งต่อไปยังตัวเกมในรูปของ `window.GAME.rules`
- `game.js` — โค้ดของเกมที่เอเจนต์ใช้แก้ไข โดยจะเปิดฟังก์ชัน `window.__gameState()` สำหรับการทดสอบเล่น, `window.__autoplay(state)` (ตัวเลือกเสริม) สำหรับเกมที่ไม่ได้บังคับด้วยปุ่มลูกศร และ `window.__renderSlots(size)` เพื่อให้แถบด้านข้างแสดงตัวละครที่วาดด้วยโค้ดได้ (เทมเพลต 2D จะวาดไว้ใน `drawCharacter()`)
- `assets/` — รูปภาพสำหรับแต่ละช่องพร้อมทั้ง `ASSETS.json` ซึ่งใช้บันทึกที่มาของแต่ละภาพ คุณสามารถวาดทับไฟล์ของช่องนั้นได้โดยตรง และสตูดิโอจะบันทึกไว้ว่าเป็นการแก้ไขของคุณ
- `dist/index.html` — บิลด์ปัจจุบัน ส่วน `.studio/` จะเก็บเวอร์ชันต่าง ๆ ภาพตัวเลือก และประวัติการรันทดสอบเล่น
